# Исправление 2026-05-05: миграции, чат и аватар

## Проблема

После добавления общего чата и настроек профиля возникли ошибки:

- аватар не загружался;
- общий чат не работал;
- при загрузке аватара Laravel возвращал SQL-ошибку:

```text
SQLSTATE[42S22]: Column not found: 1054 Unknown column 'avatar_path' in 'field list'
```

## Причина

Код уже содержал новую функциональность, но база данных еще не была обновлена.

В статусе миграций три новые миграции были в состоянии `Pending`:

- `2026_05_05_130000_add_profile_fields_and_parent_role_to_users`;
- `2026_05_05_140000_create_chat_messages_table`;
- `2026_05_05_150000_create_teacher_vote_tables`.

Из-за этого в базе отсутствовали:

- колонка `users.avatar_path`;
- колонка `users.must_change_password`;
- таблица `chat_messages`;
- таблица `vote_nominations`;
- таблица `teacher_votes`.

Именно поэтому загрузка аватара падала при `UPDATE users SET avatar_path = ...`, а чат падал при чтении таблицы `chat_messages`.

## Что сделано

Выполнены команды:

```bash
cd backend
php artisan migrate
php artisan storage:link
```

Результат:

- миграция профиля и роли родителей применена;
- миграция общего чата применена;
- миграция голосований за учителей применена;
- `storage:link` уже существовал, поэтому Laravel сообщил `The [public/storage] link already exists` — это не ошибка.

## Проверки после исправления

Проверено через `migrate:status`:

- все миграции имеют статус `Ran`;
- новые миграции находятся в batch `3`.

Проверено через `Schema`:

- `users.avatar_path` существует;
- `users.must_change_password` существует;
- таблица `chat_messages` существует;
- таблица `vote_nominations` существует.

Проверено через API:

- отправка сообщения в общий чат работает;
- чтение сообщений общего чата работает;
- SSE-поток `GET /api/chat/stream` возвращает события `message` и keep-alive `ping`;
- загрузка аватара через `POST /api/profile/avatar` работает и возвращает `Аватар обновлен`.

Тестовые данные после проверки удалены:

- тестовое сообщение `Проверка чата после миграций`;
- тестовый аватар пользователя `admin`.

## Вывод

Дефект был не в логике чата или загрузке аватара, а в непримененных миграциях базы данных.

Для любого окружения после получения последних изменений нужно выполнить:

```bash
cd backend
php artisan migrate
php artisan storage:link
```

Без этого новый функционал профиля, чата и голосований работать не будет.
